# address-atlas

Address formats, postal code rules, provinces and translated form labels for
every country, in one dataset with Go and TypeScript packages.

- **250 countries**: field order, required fields, envelope layout, which
  fields are written in capitals.
- **Postal codes**: pattern, real examples (use the first as a placeholder),
  and the rule that turns what people type into the standard form
  (`sw1a1aa` → `SW1A 1AA`, `1000001` → `100-0001`, `941051234` → `94105-1234`).
- **Provinces**: ISO 3166-2 codes for every country whose addresses name a
  state, province or prefecture. Retired codes stay valid as aliases.
- **139 languages**: field labels (“PIN code”, “Postcode”, “Prefecture”),
  country names and province names, plus validation messages.

Nothing falls back at runtime. Every country, province and language has an
explicit value, and the build fails if one is missing.

## Stable identifiers

Store and exchange codes, never display names:

| What | Identifier |
|---|---|
| Country | ISO 3166-1 alpha-2 (`GB`) |
| Province | ISO 3166-2 (`IN-MH`), or `CC-NAME` where ISO has no code |
| Field | `first_name`, `last_name`, `company`, `address1`, `address2`, `district`, `city`, `province_code`, `postal_code`, `country_code`, `phone` |

`codes.json` lists every identifier ever published. A release that removes one
is refused, so a saved code never stops resolving.

## Go

```go
import atlas "github.com/tringify/address-atlas"

gb, _ := atlas.Get("GB")
code, err := gb.NormalizePostal("sw1a1aa") // "SW1A 1AA"

l, _ := atlas.LocaleFor("de")
lines, _ := atlas.Format(atlas.Address{
	FirstName: "Asha", LastName: "Rao", Address1: "12 MG Road", City: "Mumbai",
	ProvinceCode: "IN-MH", PostalCode: "400001", CountryCode: "IN",
}, "de") // [Asha Rao, 12 MG Road, Mumbai 400001, Maharashtra, Indien]
_ = l.Labels["postal.pin"]
```

## TypeScript

```sh
npm install address-atlas
```

```ts
import { getCountry, normalizePostal, postalPlaceholder, loadLocale, formatAddress } from "address-atlas";

normalizePostal("NL", "1234ab");   // "1234 AB"
postalPlaceholder("CA");           // "H3Z 2Y7"
getCountry("JP").layout;           // form rows in Japanese order

const fr = await loadLocale("fr", (l) => import(`address-atlas/i18n/${l}.json`).then((m) => m.default));
fr.labels["province.prefecture"];  // "Préfecture"
```

Translations are one file per language (`data/i18n/<lang>.json`) so an app
loads only what it shows.

## Data

`data/` is generated by `tools/build.py` from the pinned sources in
`sources/` and the reviewed additions in `curated/`:

- Google's address metadata (libaddressinput), checked country by country
  against each postal operator's and the UPU's addressing documents;
- Unicode CLDR for country and province names;
- Chromium's translations of the address form labels;
- ISO 3166-2 for province codes.

Where these sources had gaps (labels and names in less common languages,
postal formats that changed), the values were written from official sources
and checked independently; `provenance` in each language file says where every
value came from. Sources and licences are listed in `NOTICE`.

A scheduled check compares the data with its sources every week and opens an
issue when something changes.
